\begin{abstract}
Autonomous coding agents such as Google Antigravity (\texttt{agy}), Anthropic Claude Code (\texttt{claude}), and OpenAI Codex CLI (\texttt{codex}) execute multi-step software engineering workflows on developer workstations and cloud hosts. Existing agent execution environments face a \emph{Security--Autonomy Dilemma}: operators must choose between per-action confirmation prompts, which interrupt workflows on 45\%--57\% of tool calls in our benchmark trajectories and induce severe authorization fatigue, or unconfined execution (\texttt{--yolo} / \texttt{--dangerously-skip-permissions}), which exposes host files, SSH/cloud credentials, and API tokens to prompt injection and hallucination risks. Furthermore, concurrent agents editing a shared working tree clobber one another's changes, while passing large artifacts inline through LLM context windows incurs high token overhead.

We present \textbf{Aegis OS} (\texttt{aegis-os}), a transactional, multi-tenant Agent Operating System Runtime written in Rust and exposed via the Model Context Protocol (MCP). Aegis OS shifts the authorization boundary from individual tool calls to \emph{transactional workspace boundaries}. Each agent operates inside a kernel-enforced OS sandbox (evaluated on macOS Seatbelt \texttt{sandbox-exec}, with a Linux Bubblewrap namespace backend and microVM control-plane interface) backed by an APFS Copy-on-Write (CoW) shadow workspace (\texttt{libc::clonefile}), an identity-pinned HTTP Egress Proxy with boundary secret injection, and an intra-organization Inter-Agent Communication (IPC) bus paired with Content-Addressable Storage (CAS). Inside its isolated CoW workspace and organization IPC bus, an agent executes with zero confirmation prompts; human approval or TTL-scoped session leases are required only when committing diffs to the host via an LCS-based Diff3 3-Way Merge Engine. Across 1,500 runtime tool calls spanning five trajectory templates and 40 end-to-end adversarial attacks, Aegis OS reduces human confirmation prompts by \textbf{94.19\%--99.88\%}, lowers the attack success rate on evaluated vectors from \textbf{100.0\% to 0.0\%}, clones 1,000-file (78.1 MB) workspaces in \textbf{6.28 ms} (\textbf{18.0$\times$ faster} than full copy), and preserves 100\% of disjoint multi-agent edits while catching 10/10 overlapping line conflicts.
\end{abstract}

\section{Introduction}

The paradigm of AI-assisted software engineering has shifted from passive single-line code completion to autonomous, long-horizon coding agents---such as Google Antigravity (\texttt{agy}), Anthropic Claude Code (\texttt{claude}), OpenAI Codex CLI (\texttt{codex}), SWE-agent~\cite{yang2024sweagent}, and OpenHands~\cite{wang2025openhands}. Unlike conversational assistants, coding agents iteratively explore repositories, modify files across multiple modules, invoke compilers and test suites, query external APIs, and coordinate subtasks with peer agents~\cite{jimenez2024swebench,anthropic2024mcp}.

Despite advances in model reasoning, the execution substrate for local coding agents remains caught between usability and safety. When agent CLIs mutate the developer's live working tree directly, every file write (\texttt{fs\_write}, \texttt{fs\_edit}) and shell command (\texttt{proc\_exec}) carries immediate side effects on the host. Consequently, agent frameworks rely heavily on \emph{action-level human-in-the-loop (HITL) confirmation prompts}.

\subsection{The Security--Autonomy Dilemma}

In practice, action-level prompting and existing in-place CLI sandboxes exhibit three systemic limitations:

\begin{enumerate}
    \item \textbf{Severe Authorization Fatigue:} A 30-step bug-fix, refactoring, or security-audit trajectory typically invokes 13 to 18 mutating or state-changing operations. Prompting the developer on 45\%--57\% of tool invocations (as measured in \S\ref{sec:eval}) fragments autonomous workflow continuity to streaks of 4--7 steps and habituates users to reflexively approve prompts without inspecting arguments---a well-documented failure mode in usable security~\cite{felt2012android,akhawe2013alice}.
    \item \textbf{Risk of Unconfined ``YOLO'' Mode and In-Place Mutation:} To avoid constant interruptions, developers frequently enable bypass flags (\texttt{--dangerously-skip-permissions}, \texttt{--yolo}) or rely on lightweight in-place CLI sandboxes (e.g., Claude Code or Codex native Seatbelt/Landlock modes). In unconfined mode, an indirect prompt injection~\cite{greshake2023not,debenedetti2024agentdojo,zhan2024injecagent} can overwrite files outside the repository, read host credentials (\texttt{\textasciitilde/.ssh/id\_rsa}, \texttt{\textasciitilde/.aws/credentials}, \texttt{\textasciitilde/.kube/config}), or exfiltrate raw API keys (\texttt{\$GITHUB\_TOKEN}) from process environment variables. Even when native CLI sandboxes restrict writes to the project directory, agents still mutate the live host working tree in place without transactional rollback or boundary secret injection.
    \item \textbf{Multi-Agent Workspace Collisions and Context Bloat:} Developers increasingly run heterogeneous agents in parallel (e.g., \texttt{agy} for architecture, \texttt{claude} for backend logic, and \texttt{codex} for test generation)~\cite{wu2023autogen,hong2024metagpt}. When sharing a live working directory without manual \texttt{git worktree} management, concurrent edits overwrite one another's changes, while passing large specifications inline through JSON/text messages bloats LLM context windows.
\end{enumerate}

\subsection{Key Insight: Transaction-Boundary Security}

Inspired by operating system transactions~\cite{porter2009txos,nightingale2005speculator} and user-space filesystem sandboxes~\cite{kim2013mbox,wright2004unionfs}, our key insight is that \emph{authorization prompts should not guard speculative intermediate actions inside an isolated state space; they should guard irreversible boundary crossings into the host repository or untrusted external networks}.

In Aegis OS, each agent principal is provisioned with: (1) an isolated Copy-on-Write (CoW) shadow workspace cloned from the host repository via APFS \texttt{libc::clonefile}, (2) a kernel-enforced OS sandbox that confines child processes and outbound sockets to that shadow workspace and a local loopback proxy, and (3) a local Zero-Trust Egress Proxy that strips raw credentials from the agent's environment and injects secrets only at the network boundary for allowlisted domains. Because intermediate file edits, builds, test runs, and intra-organization IPC messages cannot mutate the host tree or leak raw credentials, Aegis OS auto-allows 100\% of in-sandbox operations with zero prompts, deferring human review (or session lease evaluation) to an atomic two-phase \texttt{workspace\_commit} operation (Table~\ref{tab:substrates}).

\subsection{Contributions}

We design, implement, and evaluate \textbf{Aegis OS} (\texttt{aegis-os}), a multi-tenant Agent Operating System Runtime in Rust:

\begin{itemize}
    \item \textbf{Transactional CoW VFS with Two-Phase LCS Diff3 Merge (\S\ref{sec:vfs}):} \texttt{aos-vfs} uses APFS \texttt{libc::clonefile} syscalls to provision isolated shadow workspaces in $O(|F|)$ metadata time (0.71--6.28 ms for 100--1,000 files), supports metadata-time snapshots and rollbacks while preserving compiler build caches (\texttt{CARGO\_TARGET\_DIR}) outside the rollback tree, and implements a two-phase Longest Common Subsequence (LCS) Diff3 3-Way Merge Engine~\cite{khanna2007formal} that reconciles concurrent edits from heterogeneous agents while aborting cleanly on overlapping line conflicts.
    \item \textbf{Kernel Sandbox and Identity-Pinned Egress Proxy (\S\ref{sec:sandbox}):} \texttt{aos-sandbox} and \texttt{aos-egress} enforce mandatory access control via macOS Seatbelt (\texttt{/usr/bin/sandbox-exec} with file-write, credential-read, AppleEvent, and exact proxy-port network confinement) and a Linux Bubblewrap (\texttt{bwrap}) namespace driver, paired with a TCP-pinned HTTP Egress Proxy that injects \texttt{\$AOS\_SECRET\_*} tokens at the network boundary.
    \item \textbf{Inter-Agent IPC Bus and Reference-Based CAS (\S\ref{sec:ipc}):} \texttt{aos-ipc} provides P2P mailboxes, correlated RPC (\texttt{ipc\_request}/\texttt{ipc\_reply}) with broadcast wakeup, topic Pub/Sub, and Content-Addressable Storage (\texttt{artifact://<org>/sha256:<hash>}) that reduces in-transit IPC payload tokens by 99.85\%.
    \item \textbf{Cedar-Inspired Policy Engine with Commit-Time Poisoning Guards (\S\ref{sec:policy}):} \texttt{aos-policy} implements a five-stage authorization hierarchy inspired by Cedar~\cite{cutler2024cedar}, combining host red-line protection and commit-time sensitive path guards (\texttt{.git/hooks}, \texttt{.envrc}, \texttt{.github/workflows}) with one-shot and TTL-scoped session leases.
    \item \textbf{Empirical Evaluation (\S\ref{sec:eval}):} We evaluate Aegis OS on Apple Silicon across 1,500 runtime tool calls, 40 end-to-end process/socket/gateway red-team attacks, multi-scale APFS CoW working-set benchmarks, and multi-agent Rust compilations (\texttt{cargo test} and \texttt{cargo check}).
\end{itemize}

\section{Threat Model and Problem Formulation}
\label{sec:threat}

\subsection{System and Adversary Model}

We consider a multi-agent deployment where autonomous coding agents $\mathcal{A} = \{a_1, a_2, \dots, a_m\}$ operate within one or more tenant organizations $\mathcal{O} = \{o_1, o_2, \dots, o_k\}$. Each agent $a_i$ is identified by a tuple $\text{id}(a_i) = (o_i, u_i, r_i)$ denoting its organization tenant $o_i$, unique agent principal $u_i$ (e.g., \texttt{agy-agent}, \texttt{claude-code}, \texttt{codex-cli}), and role $r_i$.

\paragraph{Trusted Computing Base and Enforcement Assumption.} We trust the host operating system kernel (macOS XNU/Seatbelt or Linux kernel namespaces) and the Aegis OS Runtime binary (\texttt{aegis-os}), which executes outside the agent sandbox. Because MCP is an additive tool protocol, our security guarantees assume that the host agent client is configured to route filesystem mutations and shell execution through \texttt{aegis-os} (i.e., built-in unconfined host tools such as raw \texttt{Bash} or host \texttt{Write} are either disabled in client permissions or intercepted by client \texttt{PreToolUse} hooks, as detailed in \S\ref{sec:integration}).

\paragraph{Adversarial Threat Vectors (T1--T5).} We assume the LLM driving any agent $a_i \in \mathcal{A}$ is untrusted and may issue malicious or erroneous tool calls due to:
\begin{itemize}
    \item \textbf{T1 (Indirect Prompt Injection):} Malicious instructions embedded in repository files, commit logs, issue trackers, or web pages read by the agent~\cite{greshake2023not,debenedetti2024agentdojo}.
    \item \textbf{T2 (Host Path Escape and Tampering):} Attempting to write files outside the workspace (e.g., \texttt{../../etc/hosts}, \texttt{\textasciitilde/.zshrc}, or sibling repositories) or staging commit-time hooks (\texttt{.git/hooks/pre-commit}, \texttt{.envrc}).
    \item \textbf{T3 (Credential Harvesting):} Attempting to read sensitive host credentials (\texttt{\textasciitilde/.ssh/id\_rsa}, \texttt{\textasciitilde/.aws/credentials}, \texttt{\textasciitilde/.gnupg}, \texttt{\textasciitilde/.kube/config}, \texttt{\textasciitilde/.npmrc}, or macOS Keychains).
    \item \textbf{T4 (Network Secret Exfiltration):} Attempting to transmit API tokens or source code to unauthorized external domains (\texttt{evil-exfil.org}, \texttt{webhook.site}) via HTTP requests or direct socket bypass (\texttt{curl --noproxy '*'}).
    \item \textbf{T5 (Cross-Tenant Privilege Escalation):} Attempting to read CAS artifacts or inject IPC messages into a different tenant organization $o_j \neq o_i$.
\end{itemize}

\paragraph{Non-Adversarial Concurrency and Reliability Hazards (H1--H2).} Even in benign settings, multi-agent workflows face: \textbf{(H1) Concurrent Lost Updates}, where parallel agents overwrite one another's edits on shared files; and \textbf{(H2) Multi-File Hallucinated Corruption}, where an agent breaks syntax across dozens of modules during speculative refactoring.

\subsection{Evaluation Metrics}

Let an agent trajectory $\tau = (s_1, s_2, \dots, s_T)$ be a sequence of $T$ runtime tool calls. Let $\text{Prompt}(s_t) \in \{0, 1\}$ indicate whether call $s_t$ halts execution to request interactive human approval. We define the \textbf{Interruption Prompt Rate (IPR)} across a workload $\mathcal{T}$ as:
\begin{equation}
    \text{IPR}(\mathcal{T}) = \frac{\sum_{\tau \in \mathcal{T}} \sum_{s_t \in \tau} \text{Prompt}(s_t)}{\sum_{\tau \in \mathcal{T}} |\tau|} \times 100\%
\end{equation}
and the modeled \textbf{Human Verification Wait Time} $T_{\text{human}}(\mathcal{T})$ as:
\begin{equation}
    T_{\text{human}}(\mathcal{T}) = \bar{t}_{\text{verify}} \cdot \sum_{\tau \in \mathcal{T}} \sum_{s_t \in \tau} \text{Prompt}(s_t)
\end{equation}
where $\bar{t}_{\text{verify}}$ models the average human context-switch and inspection time per prompt ($\bar{t}_{\text{verify}} = 5.0\text{ s}$). We define the \textbf{Maximum Autonomous Streak (MAS)} as the longest contiguous subsequence of tool calls executed with $\text{Prompt}(s_t) = 0$. Given an adversarial suite $\mathcal{E}_{\text{adv}}$, the \textbf{Attack Success Rate (ASR)} is the fraction of attacks that violate host integrity, read restricted credentials, exfiltrate secrets, or breach tenant isolation.

\subsection{Transactional CoW Virtual Filesystem and Two-Phase LCS Diff3 Merge (\texttt{aos-vfs})}
\label{sec:vfs}

To eliminate confirmation prompts on file mutations without risking host corruption, \texttt{aos-vfs} isolates every agent principal $u_i$ inside an independent Copy-on-Write shadow workspace rooted at:
\begin{center}
{\footnotesize\texttt{<runtime\_dir>/orgs/$o_i$/agents/$u_i$/cow\_workspace/\allowbreak upper\_workspace/}}
\end{center}
(where \texttt{<runtime\_dir>} defaults to \texttt{/tmp/\allowbreak aegis-os-runtime} or \texttt{\textasciitilde/.aegis-os}), alongside a baseline directory \texttt{baseline\_snapshot/} recording the host repository state at session initialization or last commit, and a \texttt{snapshots/<snap\_id>/} directory storing time-travel checkpoints.

\paragraph{APFS \texttt{clonefile} Shadow Provisioning.} Copying a multi-megabyte repository per agent via user-space read/write loops scales as $O(|B|)$ in total byte volume. On macOS (APFS), \texttt{aos-vfs} invokes the native XNU syscall \texttt{libc::clonefile(src, dst, 0)} on eligible directory subtrees and files (automatically skipping heavy build/VCS directories such as \texttt{.git}, \texttt{target}, and \texttt{node\_modules}). Because \texttt{clonefile} duplicates only filesystem metadata extents and shares physical blocks until mutated, workspace initialization scales as $O(|F|)$ in inode count (independent of file byte size $|B|$) and allocates $O(\Delta)$ physical storage only for modified files. Unlike \texttt{git worktree}, which requires a valid git commit history, shares the repository object store, and cannot snapshot dirty untracked trees in sub-millisecond time, \texttt{aos-vfs} operates transparently on any directory and supports instant nested checkpoints.

\paragraph{Time-Travel Snapshots, Rollback, and Build-Cache Preservation.} Before speculative multi-file edits, an agent calls \texttt{workspace\_snapshot(label)}, creating a CoW clone under \texttt{snapshots/<snap\_id>/}. If compilation fails, \texttt{workspace\_rollback(snap\_id)} replaces \texttt{upper\_workspace/} with a fresh CoW clone of the snapshot in milliseconds. To prevent rollbacks from invalidating incremental compiler caches, \texttt{aos-sandbox} redirects \texttt{CARGO\_TARGET\_DIR} to \texttt{agent\_home/cargo\_target} outside \texttt{upper\_workspace/}.

\paragraph{Two-Phase LCS Diff3 3-Way Merge Engine.} When multiple agents ($u_1 = \texttt{agy-agent}$, $u_2 = \texttt{claude-code}$, $u_3 = \texttt{codex-cli}$) concurrently edit the same file $f$ in their shadow workspaces and sequentially invoke \texttt{workspace\_commit}, a naive overwrite causes a Lost Update (Hazard H1). Aegis OS prevents this via a two-phase Longest Common Subsequence (LCS) Diff3 3-Way Merge algorithm~\cite{khanna2007formal} over three states per modified path $p$: the agent's recorded baseline $B(p)$, the live host file $H(p)$, and the agent's shadow file $S(p)$.
In \textbf{Phase 1 (Validation \& Staging)}, Aegis OS inspects all modified, added, and deleted files across the commit batch. If $H(p) = B(p)$, $S(p)$ is staged for fast-forward CoW clone replacement. If $H(p) \neq B(p)$, Aegis OS computes the LCS edit scripts $\Delta(B, H)$ and $\Delta(B, S)$ as half-open baseline line intervals $[b_{\text{start}}, b_{\text{end}})$. Disjoint hunks modified only in $H(p)$ or only in $S(p)$---including multi-line structural insertions that shift downstream line numbers---are spliced together automatically. If any file in the batch has overlapping hunks where $H_{\text{hunk}} \neq S_{\text{hunk}}$, Phase 1 aborts the entire commit before mutating any host file and returns a line-level conflict diagnostic. In \textbf{Phase 2 (Commit Application)}, all staged merges and CoW clones are applied to the host repository and updated in \texttt{baseline\_snapshot/}. Conversely, when a long-lived agent resumes a session after external host commits or peer merges, \texttt{refresh\_from\_host()} rebases the shadow workspace onto the latest host state---fast-forwarding unmodified files and applying 3-way Diff3 merges to files with uncommitted local shadow edits.

\subsection{Dual-Tier OS Sandbox and Zero-Trust Egress Proxy (\texttt{aos-sandbox}, \texttt{aos-egress})}
\label{sec:sandbox}

While \texttt{aos-vfs} mediates MCP file tools, coding agents also spawn compilers, test runners, and shell scripts via \texttt{proc\_exec}. To prevent child processes from bypassing workspace or network boundaries, \texttt{aos-sandbox} provides a pluggable \texttt{SandboxDriver} with two tiers:

\begin{enumerate}
    \item \textbf{Tier 1 (\texttt{NativeOsSandboxDriver}, Workstation Kernel Enforcement):} On macOS, every \texttt{proc\_exec} call compiles a canonicalized Seatbelt Mandatory Access Control profile (SBPL) and spawns the child process under \texttt{/usr/bin/sandbox-exec -p <profile>} with a sanitized environment (\texttt{env\_clear()}). The generated profile blocks AppleEvent IPC (\texttt{(deny appleevent-send)}), denies all file writes globally (\texttt{(deny file-write*)}), allowlists writes strictly to the agent's CoW shadow workspace, private agent home, and organization publish directory, blocks reads to sensitive credential paths, and---when an egress proxy is bound---restricts outbound network sockets exclusively to the exact loopback port of the agent's proxy:
\begin{lstlisting}
(version 1)
(allow default)
(deny appleevent-send)
(deny file-write*)
(allow file-write*
  (subpath "/private/.../upper_workspace")
  (subpath "/private/.../home")
  (subpath "/private/.../pub/agy-agent")
  (literal "/dev/null") (literal "/dev/zero") (literal "/dev/tty")
  (literal "/dev/random") (literal "/dev/urandom"))
(deny file-read*
  (regex #".*/\.ssh(/.*)?$")   (regex #".*/\.aws(/.*)?$")
  (regex #".*/\.gnupg(/.*)?$") (regex #".*/\.kube(/.*)?$")
  (regex #".*/\.npmrc$")       (regex #".*/\.pypirc$")
  (regex #".*/\.config/gh(/.*)?$")
  (regex #".*/Library/Keychains(/.*)?$")
  (literal "/etc/shadow"))
(deny network-outbound)
(allow network-outbound (remote ip "localhost:51691"))
\end{lstlisting}
    Because \texttt{(deny network-outbound)} is enforced by the XNU kernel socket filter and allows only \texttt{localhost:<proxy\_port>} (without permitting wildcard localhost ports or \texttt{mDNSResponder}), a child process running \texttt{curl --noproxy '*'} or opening raw sockets to external IPs or other local services fails immediately with \texttt{Operation not permitted}. On Linux, \texttt{NativeOsSandboxDriver} constructs Bubblewrap (\texttt{/usr/bin/bwrap}) arguments with \texttt{--unshare-all} (unsharing user, mount, PID, IPC, and network namespaces when an egress proxy is bound), read-only root binds (\texttt{--ro-bind / /}), writable binds only for the shadow workspace and agent home, and empty \texttt{--tmpfs} overlays masking \texttt{\textasciitilde/.ssh}, \texttt{\textasciitilde/.aws}, \texttt{\textasciitilde/.gnupg}, and \texttt{\textasciitilde/.kube}.
    \item \textbf{Tier 2 (\texttt{MicroVmSandboxDriver}, Cloud Control-Plane Interface):} Provides the configuration generator (\texttt{virtio-fs} mount tags, vCPU/memory limits) and Scale-to-Zero \texttt{pause()}/\texttt{resume()} state machine for cloud microVM backends (\texttt{libkrun} / Firecracker~\cite{agache2020firecracker}).
\end{enumerate}

\paragraph{Identity-Pinned Egress Proxy with Boundary Secret Injection.} To mitigate credential exfiltration (Threat T4), agents inside Aegis OS do not receive raw API keys in environment variables. Instead, they receive opaque placeholders such as \texttt{\$AOS\_SECRET\_GH}. Outbound HTTP traffic is routed through a local asynchronous L7 HTTP proxy (\texttt{start\_local\_proxy\_with\_bound\_identity}). Because each sandbox listener pins its \texttt{AgentIdentity} at the TCP socket level, a compromised process cannot spoof \texttt{X-Aegis-Org} or \texttt{X-Aegis-Agent} headers. On each request, the gateway first checks all headers for \texttt{\$AOS\_SECRET\_*} placeholders against the secret vault's per-secret domain binding, and then checks the target \texttt{Host} against the organization's domain allowlist:
\begin{itemize}
    \item If \texttt{\$AOS\_SECRET\_GH} (bound to \texttt{api.github.com}) is sent toward \texttt{api.github.com}, the proxy substitutes the real token \texttt{ghp\_...} at the network boundary (returning a deterministic L7 verification response in local offline/benchmark mode or forwarding upstream).
    \item If an agent attempts to send \texttt{\$AOS\_SECRET\_GH} to any other domain (even an otherwise allowlisted domain such as \texttt{httpbin.org}, or an attacker host such as \texttt{evil-exfil.org}), the proxy rejects the request with \texttt{HTTP/1.1 403 Forbidden} (\texttt{blocked\_exfiltration}).
\end{itemize}

\subsection{Inter-Agent IPC Bus and Reference-Based CAS (\texttt{aos-ipc})}
\label{sec:ipc}

To support multi-agent coordination without shared-directory polling, \texttt{aos-ipc} provides a disk-synchronized, broadcast-enabled communication bus scoped to each organization tenant $o_i$:
\begin{itemize}
    \item \textbf{P2P Mailboxes and Correlated RPC:} Agents exchange structured envelopes via \texttt{ipc\_send}, \texttt{ipc\_recv}, \texttt{ipc\_request}, \texttt{ipc\_reply}, and \texttt{ipc\_ack}. Using \texttt{tokio::sync::broadcast} paired with persistent state (\texttt{ipc\_state.json}), cross-process stdio and HTTP agents receive immediate wakeup notifications when correlated RPC replies arrive.
    \item \textbf{Topic Pub/Sub Fanout:} Agents subscribe to organizational topics (\texttt{ipc\_subscribe}) and broadcast events via \texttt{ipc\_publish}.
    \item \textbf{Advisory-but-Enforced File Claims:} Before editing shared modules, agents invoke \texttt{coord\_claim} (and \texttt{coord\_release} upon completion) to register glob-based file leases stored as versioned CAS read-modify-write entries (\texttt{coordination/claims} in \texttt{aos-vfs}) and broadcast on \texttt{topic://coordination}. Claims held by live peers (verified via heartbeat liveness) are enforced both at pre-tool-use time and during \texttt{workspace\_commit} (\texttt{claim\_conflict\_for\_paths}), preventing concurrent edit collisions before merge time.
    \item \textbf{Reference-Based CAS Artifact Handles:} Instead of embedding a 64 KB specification or patch inline inside an IPC message payload, the sender calls \texttt{org\_artifact\_publish}, which writes the blob to the organization's Content-Addressable Store and returns a compact SHA-256 URI (\texttt{artifact://<org>/sha256:<64-hex>}, $\sim$85--98 bytes). Passing this URI handle in IPC envelopes eliminates redundant inline serialization across orchestrator and peer message queues (reducing in-transit IPC payload tokens by \textbf{99.85\%}); receiving agents that need to inspect the full content fetch it on demand via \texttt{org\_artifact\_fetch}.
\end{itemize}

\subsection{Cedar-Inspired Policy Engine and Runtime Design Invariants (\texttt{aos-policy})}
\label{sec:policy}

Every runtime tool call is evaluated by \texttt{AegisPolicyKernel::\allowbreak evaluate} using a five-stage deterministic hierarchy inspired by Cedar~\cite{cutler2024cedar}:
{\footnotesize
\begin{align}
    \text{R0a (Red-Line):} \; & \text{res} \in \mathcal{P}_{\text{forbidden}} \implies \textbf{Deny} \nonumber \\
    \text{R0b (Hook Guard):} \; & \text{act} = \texttt{workspace\_commit} \nonumber \\
    & \land \text{paths} \cap \mathcal{P}_{\text{hooks}} \neq \emptyset \implies \textbf{Ask}(\text{esc\_id}) \nonumber \\
    \text{R1 (Tenant):} \; & o_{\text{principal}} \neq o_{\text{target}} \implies \textbf{Deny} \nonumber \\
    \text{R2 (Lease):} \; & \exists \ell \in \mathcal{L}_{\text{active}}(o, u, \text{act}) \implies \textbf{Allow} \nonumber \\
    \text{R3 (Green Zone):} \; & \text{act} \in \mathcal{S}_{\text{internal}} \cup \mathcal{S}_{\text{egress}} \implies \textbf{Allow} \nonumber \\
    \text{R4 (Boundary):} \; & \text{act} \in \{\texttt{workspace\_commit}, \nonumber \\
    & \texttt{egress\_unlisted}\} \implies \textbf{Ask}(\text{esc\_id}) \nonumber
\end{align}
}
where $\mathcal{P}_{\text{forbidden}} = \{\texttt{\textasciitilde/.ssh}, \allowbreak \texttt{\textasciitilde/.aws}, \allowbreak \texttt{\textasciitilde/.gnupg}, \allowbreak \texttt{\textasciitilde/.kube}, \allowbreak \texttt{/etc/shadow}, \allowbreak \texttt{/etc/sudoers}, \allowbreak \texttt{/System}\}$ is the host red-line set, and $\mathcal{P}_{\text{hooks}} = \{\texttt{.git/hooks/*}, \allowbreak \texttt{.git/config}, \allowbreak \texttt{.envrc}, \allowbreak \texttt{.github/workflows/*}\}$ is the \textbf{Commit-Time Poisoning Guard} set. Crucially, R0b is evaluated \emph{before} active session leases (R2): even if a developer grants a 1-hour session lease for \texttt{workspace\_commit}, any commit touching git hooks, \texttt{.envrc}, or CI workflow files bypasses the lease and forces explicit human review. When approving an escalation via \texttt{policy\_approve\_escalation}, the operator can choose either a one-shot approval (\texttt{ttl\_secs = 0}, consumed immediately on that single commit) or a TTL-scoped session lease (e.g., \texttt{ttl\_secs = 3600}).

Together, these mechanisms enforce three runtime design invariants:
\begin{itemize}
    \item \textbf{Design Invariant 1 (Pre-Commit Host Non-Interference):} \emph{For any tool call sequence $\tau = (s_1, \dots, s_k)$ containing no approved \texttt{workspace\_commit}, the host directory tree $H$ satisfies $H(\tau) = H_0$.} \emph{Enforcement sketch:} VFS tools (\texttt{fs\_write}, \texttt{fs\_edit}, \texttt{fs\_delete}) reject path traversal (\texttt{..}) and resolve all relative paths under \texttt{shadow\_root}, while \texttt{proc\_exec} enforces Seatbelt \texttt{(deny file-write*)} outside \texttt{shadow\_root}, \texttt{agent\_home}, and \texttt{org\_pub}.
    \item \textbf{Design Invariant 2 (Zero Raw Secret Exposure to Sandbox):} \emph{For every secret entry $(p_j, v_j, \mathcal{D}_j)$ in the Egress Vault, the plaintext credential $v_j$ never enters the sandboxed process environment, CLI arguments, or stdout/stderr, and is substituted into outbound HTTP headers if and only if $\text{Host}(req) \in \mathcal{D}_j$.} \emph{Enforcement sketch:} \texttt{NativeOsSandboxInstance::exec} clears the child environment (\texttt{env\_clear()}) and injects only placeholders $p_j = \texttt{\$AOS\_SECRET\_*}$; \texttt{inspect\_and\_inject} verifies $\text{Host}(req) \in \mathcal{D}_j$ before substituting $v_j$.
    \item \textbf{Design Invariant 3 (All-or-Nothing Conflict-Safe Commit):} \emph{Concurrent agent commits $(S_1, \dots, S_m)$ against baselines $(B_1, \dots, B_m)$ either produce a merged host state preserving all disjoint LCS Diff3 hunks, or abort in Phase 1 without modifying any host file when overlapping baseline intervals $[b_{\text{start}}, b_{\text{end}})$ diverge.} \emph{Enforcement sketch:} \texttt{commit\_to\_host} stages and validates all file merges in memory during Phase 1 before executing any file writes in Phase 2.
\end{itemize}

\section{Multi-Client Integration and Enforcement}
\label{sec:integration}

To minimize setup friction, \texttt{aegis-os install} automatically configures MCP server entries, per-session principal resolution, and lifecycle hooks across all three coding agent CLIs:
\begin{enumerate}
    \item \textbf{Google Antigravity (\texttt{agy}):} Registers \texttt{aegis-os} in \texttt{\textasciitilde/.gemini/config/mcp\_config.json} with eager tool loading, pre-authorizes green-zone \texttt{mcp(aegis-os/*)} tools in \texttt{settings.json} while keeping lease/approval tools (\texttt{policy\_grant\_lease}, \texttt{policy\_approve\_escalation}) under \texttt{permissions.ask}, and installs four lifecycle hooks (\texttt{SessionStart}, \texttt{PreInvocation}, \texttt{PreToolUse}, and \texttt{Stop}):
    \begin{itemize}
        \item \emph{MCP-First Tool Routing (\texttt{PreToolUse}):} Because agent CLIs still prompt on native \texttt{run\_command} invocations unless exact command strings match static allowlists, \texttt{aegis-os agy-hook} classifies native shell and file calls: Ring-0 operations (\texttt{sudo}, credential paths) are unconditionally denied; host-boundary commands (\texttt{git push}, package installs) escalate to \texttt{ask}; and in-repository shell commands and file writes are denied with a ready-to-invoke \texttt{mcp\_aegis-os\_proc\_exec} or \texttt{mcp\_aegis-os\_fs\_write} payload, steering the agent onto the zero-prompt sandboxed MCP path.
        \item \emph{Per-Session Identity \& Push Coordination (\texttt{SessionStart}, \texttt{PreInvocation}, \texttt{Stop}):} Walking parent process ancestry (\texttt{PROC\_PIDTBSDINFO} on macOS / \texttt{/proc/<pid>/stat} on Linux) assigns each concurrent client window a distinct session principal (\texttt{agy-<6hex>}) bound to its \texttt{conversationId}. On \texttt{SessionStart}, the agent's CoW shadow is rebased onto the host via \texttt{refresh\_from\_host()}; on \texttt{PreInvocation}, unread IPC messages are non-destructively peeked and injected via \texttt{injectSteps.systemMessage}; and on \texttt{Stop}, un-acknowledged \texttt{TaskRequest} messages hold the turn open (up to 2 continues) until answered, while \texttt{coord\_claim}/\texttt{coord\_release} prevent overlapping file edits across live peers.
    \end{itemize}
    \item \textbf{Anthropic Claude Code (\texttt{claude}):} Injects \texttt{aegis-os} into \texttt{\textasciitilde/.claude.json} and adds green-zone \texttt{mcp\_\_\allowbreak aegis-os\_\_*} rules to \texttt{permissions.\allowbreak allow} in \texttt{\textasciitilde/.claude/\allowbreak settings.json}.
    \item \textbf{OpenAI Codex CLI (\texttt{codex}):} Appends \texttt{[mcp\_servers.\allowbreak aegis-os]} to \texttt{\textasciitilde/.codex/\allowbreak config.toml} and piggybacks unread IPC summaries (\texttt{\_aegis\_inbox}) onto \texttt{tools/call} responses.
\end{enumerate}

\end{itemize}

Each trajectory exercises repository exploration (\texttt{fs\_glob}, \texttt{fs\_read}), checkpointing (\texttt{workspace\_snapshot}), multi-file edits (\texttt{fs\_edit}, \texttt{fs\_write}), CAS publishing (\texttt{org\_artifact\_publish}), peer IPC coordination (\texttt{ipc\_send}, \texttt{ipc\_recv}, \texttt{ipc\_publish}), diff inspection (\texttt{workspace\_diff}), and host commit (\texttt{workspace\_commit}). \subsection{Experiment 2 (RQ2): End-to-End Adversarial Security}

We execute 40 live adversarial attacks end-to-end against both an unconfined disposable victim environment (\texttt{Host-YOLO}) and \texttt{Aegis-OS}:
\begin{itemize}
    \item \textbf{Category A (10 Host Path Escape Attacks):} Spawns \texttt{sh -c "echo COMPROMISED > <outside\_target>"}. In \texttt{Host-YOLO}, all 10 outside-workspace files were created on disk ($\text{ASR} = 100.0\%$). Inside \texttt{Aegis-OS} (\texttt{proc\_exec}), \texttt{/usr/bin/sandbox-exec} denied all 10 writes at the XNU kernel boundary with \texttt{Operation not permitted} ($\text{ASR} = 0.0\%$).
    \item \textbf{Category B (10 Multi-Store Credential Harvesting Attacks):} Spawns \texttt{sh -c "cat <cred\_path>"} cycling across \texttt{\textasciitilde/.ssh/id\_rsa}, \texttt{\textasciitilde/.aws/credentials}, \texttt{\textasciitilde/.gnupg/secring.gpg}, \texttt{\textasciitilde/.kube/config}, and \texttt{\textasciitilde/.npmrc}. \texttt{Host-YOLO} leaked the secret key material on all 10 attempts ($\text{ASR} = 100.0\%$), whereas the Aegis OS Seatbelt profile blocked all 10 reads ($\text{ASR} = 0.0\%$).

In \texttt{Aegis-OS}, we execute \texttt{curl} inside a Seatbelt sandbox (\texttt{sbx\_egress.exec}) bound to \texttt{localhost:<proxy\_port>} that attempts \emph{both} (1) proxy exfiltration of \texttt{\$AOS\_SECRET\_GH} to 10 unauthorized domains (\texttt{evil-exfil.org}, \texttt{webhook.site}, \texttt{ngrok-free.app}, etc.), which the proxy rejected with \texttt{HTTP/1.1 403 Forbidden} (\texttt{blocked\_exfiltration}), and (2) direct proxy-bypass (\texttt{curl --noproxy '*' http://<sink\_addr>/bypass}), which the XNU Seatbelt socket filter blocked with \texttt{Operation not permitted}. Zero tokens reached \texttt{sink\_addr} ($\text{ASR} = 0.0\%$).
    \item \textbf{Category D (10 Cross-Tenant IPC and CAS Attacks via MCP Gateway):} In a shared flat host store (\texttt{Host-YOLO}), an unconfined process directly read all 10 confidential enterprise tenant files ($\text{ASR} = 100.0\%$). In \texttt{Aegis-OS}, we register 10 enterprise tenants (\texttt{org-enterprise-$i$}), publish confidential CAS artifacts via \texttt{org\_artifact\_publish}, and have principal \texttt{mallory} (\texttt{org-alpha}) invoke \texttt{kernel.call\_tool} (\texttt{ipc\_send} and \texttt{org\_artifact\_fetch}) targeting \texttt{org-enterprise-$i$}. \subsection{Experiment 3 (RQ3): CoW Provisioning, Storage Footprint, and Operation Latency}

We benchmark workspace provisioning across three repository scales (100 files / 2.0 MB, 300 files / 17.6 MB, and 1,000 files / 78.1 MB, 5 trials per scale). As shown in Table~\ref{tab:exp3a} and Figure~\ref{fig:exp3}, full copying requires $113.13 \pm 16.41$ ms for the 1,000-file repository, whereas APFS \texttt{libc::clonefile} provisions the shadow workspace in \textbf{$6.28 \pm 0.65$ ms} (\textbf{18.0$\times$ faster}). Note that \texttt{clonefile} latency scales linearly with file/inode metadata count $O(|F|)$ (from 0.71 ms at 100 files to 6.28 ms at 1,000 files) rather than byte size $|B|$. Across 10 concurrent agent workspaces modifying working sets of 6, 12, and 25 files per agent, APFS CoW reduces disk block allocation by \textbf{94.0\%--97.5\%} (19.5 MB vs.\ 781.2 MB at 1,000 files).

Table~\ref{tab:exp3b} reports the latency distribution across all five runtime operation classes. In-process policy evaluation takes \textbf{0.31 $\mu$s} (310 ns, 2.96M ops/s), P2P IPC send/receive takes \textbf{1.06 $\mu$s}, a loopback HTTP JSON-RPC \texttt{fs\_read} call (\texttt{POST /mcp}) takes \textbf{177.11 $\mu$s}, a two-phase LCS Diff3 \texttt{commit\_to\_host} takes \textbf{424.02 $\mu$s}, and spawning an external process under macOS Seatbelt (\texttt{/usr/bin/sandbox-exec /usr/bin/true}) takes \textbf{6.68 ms} (6,678.97 $\mu$s). \subsection{Experiment 4 (RQ4): Multi-Agent Concurrent Rust Coding and Conflict Detection}

We evaluate both disjoint structural edits and overlapping concurrent edits across \texttt{agy-agent}, \texttt{claude-code}, and \texttt{codex-cli} on a Rust crate (\texttt{src/lib.rs}):
\begin{itemize}
    \item \textbf{Concurrent Multi-Line Insertion and Function Edits (EXP 4A):} All three agents start from the same baseline \texttt{src/lib.rs}. \texttt{agy-agent} inserts a 3-line helper function (\texttt{min\_fee()}) at the top of the file and updates \texttt{calc\_fee} (shifting downstream line indices), while \texttt{claude-code} modifies \texttt{calc\_tax} and \texttt{codex-cli} modifies \texttt{calc\_discount}. When writing directly to a shared file (\textbf{Host-Shared-YOLO}), the final writer (\texttt{codex-cli}) overwrites the earlier edits, preserving only \textbf{1/3} of the features. In \textbf{Aegis-OS}, our two-phase LCS Diff3 engine aligns the unmodified anchor lines across the unequal-length files (matching the merge semantics of \texttt{git merge-file} without requiring manual \texttt{git worktree} branches per agent), preserving \textbf{3/3 (100\%)} of the features and passing \texttt{cargo test --offline} (\texttt{exit code 0}).
    \item \textbf{Overlapping Same-Line Conflict Detection (EXP 4B):} Across 10 trials, both \texttt{agy-agent} and \texttt{codex-cli} concurrently modify \texttt{calc\_fee} with conflicting expressions. While \textbf{Host-Shared-YOLO} suffers a silent lost update (0/10 detected), \textbf{Aegis-OS} detects \textbf{10/10 (100\%)} of the conflicts during Phase 1, aborts the second commit without modifying the host file, and returns the exact conflicting baseline line number.
    \item \textbf{In-Transit IPC Token Savings:} Passing 98-byte \texttt{artifact://} CAS URI handles instead of inline 64 KB specifications across 3 inter-agent handoffs reduces in-transit IPC message payload bytes from 196,608 bytes ($\sim$49,152 tokens) to 294 bytes ($\sim$73 tokens), a \textbf{99.85\% reduction} for orchestrator routing and pass-through delegation (Table~\ref{tab:exp4}).

\section{Discussion and Limitations}
\label{sec:discussion}

\paragraph{Cross-Platform Implementation Scope (macOS vs.\ Linux).} Table~\ref{tab:crossplatform} summarizes the implementation status of each OS primitive in \texttt{aegis-os}. Our empirical evaluation in \S\ref{sec:eval} was conducted on macOS (\texttt{macos-aarch64}), where \texttt{libc::clonefile} and \texttt{/usr/bin/sandbox-exec} are exercised end-to-end. On Linux, \texttt{NativeOsSandboxDriver} generates \texttt{/usr/bin/bwrap} arguments with \texttt{--unshare-all} (including network namespace isolation when an egress proxy is configured) and mounts empty \texttt{--tmpfs} overlays over \texttt{\textasciitilde/.ssh}, \texttt{\textasciitilde/.aws}, \texttt{\textasciitilde/.gnupg}, and \texttt{\textasciitilde/.kube}; adding native Linux \texttt{ioctl(FICLONE)} reflinks~\cite{rodeh2013btrfs}, Landlock LSM, and \texttt{seccomp-bpf} syscall filters, as well as binding \texttt{MicroVmSandboxDriver} to live \texttt{libkrun}/Firecracker VMM processes, are engineering extensions for Linux cloud deployments.

\paragraph{macOS Seatbelt Architecture and Escape Surface.} On macOS, dynamic linker caches (\texttt{dyld}), Xcode toolchains, and Homebrew packages traverse numerous paths under \texttt{/System}, \texttt{/Library}, and \texttt{/opt/homebrew}. Thus, our Seatbelt profile pairs a strict write allowlist (\texttt{(deny file-write*)}) with a regex read denylist for credential stores, \texttt{(deny appleevent-send)} to prevent AppleScript/GUI automation escapes, and exact port confinement \texttt{(allow network-outbound (remote ip "localhost:<proxy\_port>"))}. While Apple has marked \texttt{/usr/bin/sandbox-exec} as a legacy interface, it remains the standard kernel MAC mechanism used by production agent CLIs (including Claude Code and Codex CLI) on macOS because Apple's Endpoint Security and \texttt{Virtualization.framework} require root entitlements or full VM boot overhead. Hardening Mach bootstrap lookups (\texttt{mach-lookup}) against LaunchServices job spawning without breaking toolchain execution is an important direction for future work.

\paragraph{Session Leases and Commit-Time Poisoning.} Granting a 1-hour session lease (\texttt{ttl=3600}) eliminates 99.88\% of prompts by allowing validated CoW diffs to commit automatically. However, if a prompt-injected agent modifies repository build scripts (e.g., \texttt{Makefile}, \texttt{build.rs}, or \texttt{package.json} \texttt{postinstall}) and commits under an active lease, a subsequent unsandboxed build on the host could execute attacker code (\emph{commit-time poisoning}). Aegis OS mitigates the most direct vectors via Rule R0b (\S\ref{sec:policy}), which refuses silent lease auto-commits whenever a diff touches \texttt{.git/hooks/*}, \texttt{.git/config}, \texttt{.envrc}, or \texttt{.github/workflows/*}. Extending R0b to require human approval on \texttt{build.rs}, \texttt{Makefile}, and \texttt{package.json} modifications is straightforward.

\paragraph{Confused Deputy on Allowlisted Egress Domains and HTTPS TLS Termination.} Boundary secret injection guarantees that raw tokens never enter the agent sandbox and cannot be sent to unauthorized domains. However, if \texttt{api.github.com} is allowlisted for \texttt{\$AOS\_SECRET\_GH}, a prompt-injected agent could still act as a \emph{confused deputy} by issuing a \texttt{POST /gists} request to exfiltrate code to a public GitHub Gist on \texttt{api.github.com}. Mitigating confused-deputy exfiltration on allowlisted domains requires restricting secret injection by HTTP method and URL path prefix (e.g., permitting \texttt{GET /repos/org/*} while escalating \texttt{POST /gists}). Additionally, intercepting headers inside direct \texttt{HTTPS CONNECT} tunnels from legacy CLI binaries requires configuring the local proxy with a session-scoped ephemeral TLS Certificate Authority (\texttt{SSL\_CERT\_FILE}).

\paragraph{Syntactic 3-Way Merging vs.\ Semantic Conflicts.} Our two-phase LCS Diff3 engine resolves disjoint line edits and aborts on overlapping line conflicts, but syntactically disjoint edits can still introduce semantic conflicts (e.g., Agent A renames a function signature at Line 10 while Agent B calls the old function name at Line 120)~\cite{apel2011semistructured}. Running \texttt{cargo test} via \texttt{proc\_exec} after merging peer changes and rolling back via \texttt{workspace\_rollback} if compilation fails mitigates semantic integration errors.

\section{Related Work}
\label{sec:related}

\paragraph{Operating System Transactions and Speculative Execution.} Our transaction-boundary security model builds on classical operating system transactions. TxOS~\cite{porter2009txos} introduced kernel-level system transactions (\texttt{sys\_xbegin}/\texttt{sys\_xend}) providing ACID semantics for OS resources, while Speculator~\cite{nightingale2005speculator} enabled speculative process execution over distributed filesystems with rollback on dependency failure. Mbox~\cite{kim2013mbox} and UnionFS~\cite{wright2004unionfs} layered user-space filesystem interposition above host directories to sandbox untrusted build scripts and package installations. Aegis OS adapts OS transaction semantics specifically to multi-tenant AI coding agents, combining APFS \texttt{clonefile} CoW shadow trees with two-phase LCS Diff3 merging~\cite{khanna2007formal,apel2011semistructured} and Cedar-inspired~\cite{cutler2024cedar} session leases.

\paragraph{Authorization Fatigue in Usable Security.} Empirical studies of permission systems in mobile OSes~\cite{felt2012android} and browser security warnings~\cite{akhawe2013alice} have consistently shown that high-frequency, low-context prompts induce habituation, causing users to click through warnings without comprehension. Autonomous coding agents exacerbate this phenomenon by issuing dozens of mutating tool calls per minute; Aegis OS eliminates intermediate prompts by making in-sandbox actions side-effect-free and reversible.

\paragraph{LLM Agent Sandboxes and Prompt Injection Defenses.} Benchmarks such as SWE-bench~\cite{jimenez2024swebench}, SWE-agent~\cite{yang2024sweagent}, OpenHands~\cite{wang2025openhands}, ToolEmu~\cite{ruan2024toolemu}, AgentDojo~\cite{debenedetti2024agentdojo}, and InjecAgent~\cite{zhan2024injecagent} demonstrate both the utility of coding agents and their susceptibility to indirect prompt injection~\cite{greshake2023not}. System-level defenses such as IsolateGPT~\cite{wu2024secgpt}, CaMeL~\cite{debenedetti2025camel}, and FIDES~\cite{costa2025fides} enforce privilege separation or information-flow control across LLM planners and tool interpreters. Production CLIs such as Claude Code (\texttt{sandbox-runtime}) and Codex CLI integrate Seatbelt and Bubblewrap/Landlock sandboxes to confine shell commands in place. Aegis OS complements both model-level IFC defenses and in-place CLI sandboxes by adding transactional CoW shadow workspaces, two-phase Diff3 multi-agent merge commits, boundary secret injection, and cross-agent IPC/CAS.

\paragraph{Agent Operating Systems and Multi-Agent Frameworks.} AIOS~\cite{mei2024aios} schedules LLM queries and context snapshots above application agents, while AutoGen~\cite{wu2023autogen} and MetaGPT~\cite{hong2024metagpt} coordinate multi-agent dialogues in Python. Aegis OS instead operates purely as a language-agnostic OS runtime below the MCP boundary~\cite{anthropic2024mcp}, drawing on capability systems such as Capsicum~\cite{watson2010capsicum} and microVMs such as Firecracker~\cite{agache2020firecracker}.

\section{Conclusion}
\label{sec:conclusion}

We presented \textbf{Aegis OS}, a transactional, multi-tenant Agent Operating System Runtime that addresses the Security--Autonomy Dilemma for autonomous coding agents. By combining APFS Copy-on-Write shadow workspaces, two-phase LCS Diff3 multi-agent merge commits, kernel-enforced Seatbelt/Bubblewrap sandboxes with port-pinned network confinement, boundary secret injection, and intra-organization IPC + CAS primitives, Aegis OS reduces human confirmation prompts by 94.19\%--99.88\% on our benchmark suite while blocking all 40 evaluated process, credential, network, and cross-tenant attacks.
