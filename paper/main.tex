\begin{abstract}
Autonomous coding agents such as Google Antigravity (\texttt{agy}), Anthropic Claude Code (\texttt{claude}), and OpenAI Codex CLI (\texttt{codex}) increasingly execute complex, multi-step software engineering workflows directly on developer workstations and enterprise cloud hosts. However, existing agent execution environments suffer from a fundamental \emph{Security--Autonomy Dilemma}: users must choose between \emph{Interactive Per-Action Prompting}, which interrupts human operators on 45\%--57\% of tool invocations and induces severe authorization fatigue, or \emph{Unconfined Host Execution} (\texttt{--yolo} / \texttt{--dangerously-skip-permissions}), which exposes the host filesystem, SSH/cloud credentials, and API secrets to catastrophic prompt injection and agent hallucination risks. Furthermore, when multiple heterogeneous agents collaborate on a shared repository, concurrent unconstrained edits cause race-condition file clobbering, while passing large code artifacts inline through LLM context windows incurs prohibitive token overhead.

We present \textbf{Aegis OS} (\texttt{aegis-os}), a transactional, multi-tenant Agent Operating System Runtime implemented in Rust and exposed via the Model Context Protocol (MCP). Aegis OS resolves the Security--Autonomy Dilemma by shifting the security boundary from individual tool invocations to \emph{transactional workspace boundaries}. Each agent principal operates inside a kernel-enforced OS sandbox (macOS Seatbelt \texttt{sandbox-exec} or Linux Bubblewrap/MicroVM) backed by an APFS Copy-on-Write (CoW) shadow workspace (\texttt{libc::clonefile}), a Zero-Trust HTTP Egress Proxy with boundary secret injection, and an intra-organization Inter-Agent Communication (IPC) bus paired with Content-Addressable Storage (CAS). Inside its isolated CoW workspace and organization IPC bus, an agent executes with \emph{zero confirmation prompts}; human authorization or TTL-based session leases are required only when committing validated diffs back to the host via an LCS-based Diff3 3-Way Merge Engine. Across 1,500 live kernel syscalls spanning five software engineering trajectory classes and 40 live red-team attacks, Aegis OS reduces human confirmation prompts by \textbf{94.19\%--99.88\%} (saving up to \textbf{71.6 minutes} of human verification wait time), lowers the attack success rate from \textbf{100.0\% to 0.0\%}, provisions 1,000-file (78.1 MB) workspaces in \textbf{5.75 ms} (\textbf{17.1$\times$ faster} than full copy with \textbf{94.0\%--97.5\% storage savings}), preserves \textbf{100\% of concurrent multi-agent edits} (including structural multi-line insertions) while catching \textbf{10/10 overlapping line conflicts}, and reduces cross-agent artifact handoff token consumption by \textbf{99.85\%}.
\end{abstract}

\section{Introduction}

The paradigm of AI-assisted software engineering has shifted rapidly from passive single-line code completion to autonomous, long-horizon coding agents---exemplified by Google Antigravity (\texttt{agy}), Anthropic Claude Code (\texttt{claude}), OpenAI Codex CLI (\texttt{codex}), SWE-agent~\cite{yang2024sweagent}, and OpenHands~\cite{wang2025openhands}. Unlike chat assistants, autonomous coding agents iteratively explore repositories, modify source files across multiple modules, invoke compilers and test suites, query external APIs, and delegate subtasks to peer agents~\cite{jimenez2024swebench,anthropic2024mcp}.

Despite rapid advances in foundation model reasoning, the underlying execution substrate for coding agents remains dangerously primitive. Current agent CLIs execute directly as standard user processes on the developer's host operating system. Because every file mutation (\texttt{fs\_write}, \texttt{fs\_edit}) and shell command (\texttt{proc\_exec}) carries irreversible side effects on the host machine, agent frameworks enforce safety through \emph{action-level human-in-the-loop (HITL) confirmation prompts}.

\subsection{The Security--Autonomy Dilemma}

In practice, action-level prompting breaks down under realistic software engineering workloads due to three systemic limitations:

\begin{enumerate}
    \item \textbf{Severe Authorization Fatigue:} A typical 30-step bug-fix, refactoring, or security-audit trajectory involves 15 to 20 mutating or process-spawning actions. Prompting the developer on nearly every step destroys autonomous workflow continuity (limiting the maximum autonomous streak to 4--7 actions) and trains users to reflexively click ``Approve'' without inspecting arguments.
    \item \textbf{Catastrophic Risk of ``YOLO'' Mode:} Frustrated by constant interruptions, developers routinely enable bypass flags such as \texttt{--dangerously-skip-permissions} or \texttt{--yolo}. In this unconfined mode, a single indirect prompt injection~\cite{greshake2023not,debenedetti2024agentdojo,zhan2024injecagent} embedded in a third-party dependency, issue description, or web page can silently overwrite files outside the repository, harvest \texttt{\textasciitilde/.ssh/id\_rsa}, \texttt{\textasciitilde/.aws/credentials}, or \texttt{\textasciitilde/.kube/config} credentials, or exfiltrate production API tokens (\texttt{\$GITHUB\_TOKEN}, \texttt{\$OPENAI\_API\_KEY}) to attacker-controlled endpoints.
    \item \textbf{Multi-Agent Workspace Collisions and Context Bloat:} Developers increasingly run multiple specialized agents in parallel (e.g., \texttt{agy} as Lead Architect, \texttt{claude} as Backend Specialist, and \texttt{codex} as Test Engineer)~\cite{wu2023autogen,hong2024metagpt}. When operating on a shared host directory, concurrent file writes clobber one another's changes, leaving the repository in an uncompilable state. Moreover, lacking an OS-level Inter-Process Communication (IPC) and shared memory mechanism, agents pass large specifications and diffs inline through JSON/text messages, exhausting LLM context windows.
\end{enumerate}

\subsection{Key Insight: Transaction-Boundary Security}

Our key insight is that \emph{authorization prompts should not guard speculative intermediate actions inside an isolated state space; they should only guard irreversible boundary crossings into the host environment or untrusted external networks}.

By analogy with hardware virtual memory and database transactions~\cite{kim2013mbox,wright2004unionfs}, if each agent is provisioned with (1) an instant Copy-on-Write (CoW) shadow filesystem, (2) a mandatory kernel-enforced OS sandbox that confines all spawned child processes and outbound network sockets to that shadow workspace and local proxy, and (3) a local Zero-Trust Egress Proxy that strips raw credentials from the agent's environment and injects secrets only at the network boundary for allowlisted domains, then \emph{all intermediate file edits, builds, test executions, and intra-organization agent communications become safe, side-effect-free, and instantaneously reversible}. Consequently, the OS kernel can auto-allow 100\% of in-sandbox mutations with \emph{zero human prompts}, deferring human review (or TTL-based policy lease evaluation) to a single atomic \texttt{workspace\_commit} syscall (Table~\ref{tab:substrates}).

\subsection{Contributions}

We design, implement, and empirically evaluate \textbf{Aegis OS} (\texttt{aegis-os}), a pure-environment Agent Operating System Runtime written in Rust. Our main contributions are:

\begin{itemize}
    \item \textbf{Transactional CoW VFS with LCS Diff3 3-Way Merge (\S\ref{sec:vfs}):} We build \texttt{aos-vfs}, which leverages APFS directory-tree and file-level \texttt{libc::clonefile} syscalls to provision isolated shadow workspaces in milliseconds, supports $O(1)$ metadata-time snapshots and rollbacks (while preserving incremental build caches outside the rollback tree), and integrates a Longest Common Subsequence (LCS) Diff3 3-Way Merge Engine (\texttt{three\_way\_merge\_lines})~\cite{khanna2007formal} that cleanly reconciles concurrent modifications---including multi-line structural insertions---from heterogeneous agents (\texttt{agy}, \texttt{claude}, \texttt{codex}) while detecting overlapping line conflicts.
    \item \textbf{Dual-Tier Kernel Sandbox and Zero-Trust Egress (\S\ref{sec:sandbox}):} We implement \texttt{aos-sandbox} and \texttt{aos-egress}, enforcing mandatory access control via macOS Seatbelt (\texttt{/usr/bin/sandbox-exec} with file-write, credential-read, and outbound-network confinement) and Linux Bubblewrap (\texttt{/usr/bin/bwrap}), paired with an identity-pinned TCP HTTP Egress Proxy that performs boundary secret injection (\texttt{\$AOS\_SECRET\_*}) and blocks secret exfiltration across unauthorized domains.
    \item \textbf{First-Class Inter-Agent IPC Bus and Org CAS (\S\ref{sec:ipc}):} We design \texttt{aos-ipc}, providing P2P mailboxes, correlated RPC task handoff (\texttt{ipc\_request}/\texttt{ipc\_reply}) with tokio broadcast wakeup, topic Pub/Sub, and Content-Addressable Storage (\texttt{artifact://<org>/sha256:<hash>}) that reduces cross-agent payload tokens by 99.85\%.
    \item \textbf{Cedar-Aligned Policy Kernel and Formal Safety Invariants (\S\ref{sec:policy}):} We formalize a five-stage authorization kernel (\texttt{aos-policy}) combining Ring-0 host red-line protection with TTL-based session leases~\cite{cutler2024cedar}, establish three formal kernel safety invariants, and build a zero-configuration installer (\texttt{aegis-os install}) that seamlessly integrates with \texttt{agy}, \texttt{claude}, and \texttt{codex} via MCP.
    \item \textbf{Live Empirical Benchmark Suite (\S\ref{sec:eval}):} We evaluate Aegis OS across five live empirical experiments executing 1,500 real kernel syscalls across five task templates, 40 live red-team OS process and TCP socket attacks, multi-scale APFS CoW working-set tests, and live multi-agent Rust compilations (\texttt{cargo test} and \texttt{cargo check}).
\end{itemize}

\section{Threat Model and Problem Formulation}
\label{sec:threat}

\subsection{System and Adversary Model}

We consider a multi-agent deployment where a set of autonomous coding agents $\mathcal{A} = \{a_1, a_2, \dots, a_m\}$ operate within one or more tenant organizations $\mathcal{O} = \{o_1, o_2, \dots, o_k\}$. Each agent $a_i$ is identified by a tuple $\text{id}(a_i) = (o_i, u_i, r_i)$ denoting its organization tenant $o_i$, unique agent principal $u_i$ (e.g., \texttt{agy-agent}, \texttt{claude-code}, \texttt{codex-cli}), and role $r_i$.

\paragraph{Trusted Computing Base (TCB).} We trust the host operating system kernel (macOS XNU/Seatbelt or Linux kernel/namespaces/KVM) and the Aegis OS Runtime binary (\texttt{aegis-os}), which runs outside the agent sandbox.

\paragraph{Untrusted Entities and Threat Vectors.} We assume that the LLM driving any agent $a_i \in \mathcal{A}$ is \emph{untrusted} and may issue arbitrary, erroneous, or malicious tool calls due to:
\begin{enumerate}
    \item \textbf{Indirect Prompt Injection (T1):} Malicious instructions embedded in repository files, git commit logs, issue trackers, or web pages read by the agent~\cite{greshake2023not,debenedetti2024agentdojo}.
    \item \textbf{Host Path Escape and Tampering (T2):} Attempting to overwrite files outside the project directory (e.g., \texttt{../../etc/hosts}, \texttt{\textasciitilde/.zshrc}, or sibling repositories).
    \item \textbf{Credential Harvesting (T3):} Attempting to read sensitive user credentials from the host home directory (\texttt{\textasciitilde/.ssh/id\_rsa}, \texttt{\textasciitilde/.aws/credentials}, \texttt{\textasciitilde/.gnupg}, \texttt{\textasciitilde/.kube/config}, \texttt{\textasciitilde/.npmrc}, or macOS Keychains).
    \item \textbf{Network Secret Exfiltration (T4):} Attempting to transmit API keys or private source code to unauthorized external domains (\texttt{evil-exfil.org}, \texttt{webhook.site}) via HTTP requests or shell tools (\texttt{curl --noproxy '*'}, \texttt{wget}).
    \item \textbf{Cross-Tenant Privilege Escalation (T5):} Attempting to read artifacts or send IPC instructions to an agent belonging to a different organization $o_j \neq o_i$.
    \item \textbf{Concurrent Multi-Agent Race Conditions and Hallucinated Corruption (T6):} Overwriting peer agents' concurrent edits on shared files or breaking compilation across dozens of modules during speculative refactoring.
\end{enumerate}

\subsection{Formalizing the Evaluation Metrics}

Let an agent trajectory $\tau = (s_1, s_2, \dots, s_T)$ be a sequence of $T$ kernel syscalls invoked to complete a software engineering task. Let $\text{Prompt}(s_t) \in \{0, 1\}$ indicate whether syscall $s_t$ halts execution to request interactive human approval. We define the \textbf{Interruption Prompt Rate (IPR)} across a workload $\mathcal{T}$ of $N$ trajectories as:
\begin{equation}
    \text{IPR}(\mathcal{T}) = \frac{\sum_{\tau \in \mathcal{T}} \sum_{s_t \in \tau} \text{Prompt}(s_t)}{\sum_{\tau \in \mathcal{T}} |\tau|} \times 100\%
\end{equation}
and the \textbf{Human Verification Wall-Clock Overhead} $T_{\text{human}}(\mathcal{T})$ as:
\begin{equation}
    T_{\text{human}}(\mathcal{T}) = \bar{t}_{\text{verify}} \cdot \sum_{\tau \in \mathcal{T}} \sum_{s_t \in \tau} \text{Prompt}(s_t)
\end{equation}
where $\bar{t}_{\text{verify}}$ is the average human context-switch and inspection time per prompt (conservatively $\bar{t}_{\text{verify}} = 5.0\text{ s}$). We define the \textbf{Maximum Autonomous Streak (MAS)} as the longest contiguous subsequence of syscalls executed with $\text{Prompt}(s_t) = 0$. Given an adversarial test suite $\mathcal{E}_{\text{adv}}$, the \textbf{Attack Success Rate (ASR)} is the fraction of attacks that successfully violate host integrity, read restricted credentials, exfiltrate secrets, or breach tenant isolation. Our objective is to achieve $\text{ASR} = 0.0\%$ while minimizing $\text{IPR}$ toward $0\%$.

\subsection{Transactional CoW Virtual Filesystem and LCS Diff3 3-Way Merge (\texttt{aos-vfs})}
\label{sec:vfs}

To eliminate confirmation prompts on file writes without risking host corruption, \texttt{aos-vfs} (\texttt{CoWWorkspace::init}) isolates every agent principal $u_i$ inside its own Copy-on-Write shadow workspace rooted at:
\begin{center}
{\footnotesize\texttt{\textasciitilde/.aegis-os/orgs/$o_i$/agents/$u_i$/workspace\_cow/\allowbreak upper\_workspace/}}
\end{center}
alongside a baseline snapshot directory \texttt{baseline\_snapshot/} that records the state of the host repository at session initialization or last commit, and a \texttt{snapshots/<snap\_id>/} directory storing time-travel checkpoints.

\paragraph{Kernel-Level APFS \texttt{clonefile} Provisioning.} Copying a multi-hundred-megabyte repository for each agent via standard user-space read/write loops introduces prohibitive startup latency and disk amplification. On macOS (APFS), \texttt{CoWWorkspace::cow\_sync\_dir} invokes the native XNU kernel syscall \texttt{libc::clonefile(src, dst, 0)} directly on the directory tree and individual files (falling back to \texttt{cp -cR} / Btrfs \texttt{FICLONE} on Linux~\cite{rodeh2013btrfs,wright2004unionfs}). Because \texttt{clonefile} duplicates only filesystem metadata extents and shares physical storage blocks until modified, initializing both \texttt{upper\_workspace/} and \texttt{baseline\_snapshot/} consumes zero additional data blocks for unmodified files, and cloning a 1,000-file (78.1 MB) repository completes in \textbf{5.75 ms}.

\paragraph{Time-Travel Snapshots, Atomic Rollback, and Build-Cache Preservation.} Before embarking on risky multi-file refactorings, an agent invokes \texttt{workspace\_snapshot(label)}, which creates an instant CoW clone under \texttt{snapshots/<snap\_id>/}. If a subsequent build or test fails, \texttt{workspace\_rollback(snap\_id)} atomically replaces \texttt{upper\_workspace/} with a fresh CoW clone of the snapshot in milliseconds. Crucially, to prevent rollbacks from wiping out incremental compiler caches (such as Rust's \texttt{target/} directory), \texttt{aos-sandbox} redirects \texttt{CARGO\_TARGET\_DIR} to \texttt{agent\_home/cargo\_target} outside \texttt{upper\_workspace/}, preserving warm incremental build artifacts across workspace rollbacks.

\paragraph{LCS Diff3 3-Way Merge Engine for Multi-Agent Concurrency.} When multiple agents ($u_1 = \texttt{agy-agent}$, $u_2 = \texttt{claude-code}$, $u_3 = \texttt{codex-cli}$) concurrently edit the same file $f$ in their respective shadow workspaces and sequentially invoke \texttt{workspace\_commit}, a naive file copy would overwrite earlier commits (\emph{Lost Update}). Aegis OS prevents this via a Longest Common Subsequence (LCS) Diff3 3-Way Merge algorithm (\texttt{compute\_lcs\_diff\_hunks} and \texttt{three\_way\_merge\_lines})~\cite{khanna2007formal} using three states for every modified path $p$:
\begin{itemize}
    \item $B(p)$: the agent's recorded baseline version in \texttt{baseline\_snapshot/$p$};
    \item $H(p)$: the current live file on the host repository \texttt{host/$p$} (which may already incorporate commits from peer agents);
    \item $S(p)$: the agent's modified version in \texttt{upper\_workspace/$p$}.
\end{itemize}
If $H(p) = B(p)$, the host file was untouched by peers and $S(p)$ is fast-forwarded via atomic CoW replacement. If $H(p) \neq B(p)$, Aegis OS computes the LCS edit script $\Delta(B, H)$ and $\Delta(B, S)$ as half-open baseline line intervals $[b_{\text{start}}, b_{\text{end}})$ mapped to replacement line vectors. Disjoint hunks modified only in $H(p)$ or only in $S(p)$---including multi-line structural insertions and deletions that shift subsequent line numbers---are spliced together automatically without human intervention. Conversely, overlapping hunks on $[b_{\text{start}}, b_{\text{end}})$ where $H_{\text{hunk}} \neq S_{\text{hunk}}$ atomically abort the commit before touching the host tree and return a structured conflict diagnostic identifying the exact baseline line number.

\subsection{Dual-Tier OS Sandbox and Zero-Trust Egress Proxy (\texttt{aos-sandbox}, \texttt{aos-egress})}
\label{sec:sandbox}

While \texttt{aos-vfs} intercepts MCP file syscalls (\texttt{fs\_read}, \texttt{fs\_write}, \texttt{fs\_edit}), coding agents also spawn arbitrary child compilers, test runners, and shell scripts via \texttt{proc\_exec}. If \texttt{proc\_exec} ran unconfined, a shell command could bypass the CoW workspace or Egress Proxy entirely.

\paragraph{Mandatory Kernel Sandbox (\texttt{sandbox-exec} / \texttt{bwrap} / MicroVM).} \texttt{aos-sandbox} implements a pluggable \texttt{SandboxDriver} supporting two isolation tiers:
\begin{enumerate}
    \item \textbf{Tier 1 (\texttt{NativeOsSandboxDriver}, Full Kernel Enforcement on macOS \& Linux):} Designed for low-latency local workstation execution. On macOS, every \texttt{proc\_exec} invocation dynamically compiles a canonicalized Seatbelt Mandatory Access Control profile (SBPL) and executes the child process under \texttt{/usr/bin/sandbox-exec -p <profile>}. On Linux, \texttt{NativeOsSandboxInstance::exec} invokes \texttt{/usr/bin/bwrap} using \texttt{generate\_linux\_bwrap\_args()} with unprivileged mount/PID/network namespaces (\texttt{--unshare-all}, \texttt{--ro-bind / /}, \texttt{--bind <workspace>}, and \texttt{--tmpfs} overlays hiding \texttt{\textasciitilde/.ssh} and \texttt{\textasciitilde/.aws}). The macOS Seatbelt profile denies all file writes globally (\texttt{(deny file-write*)}), allowlists writes \emph{only} to the agent's canonical CoW shadow workspace, private agent home, and organization CAS directory, blocks reads to sensitive credential stores, and confines outbound network sockets exclusively to the local Aegis Egress Proxy:
\begin{lstlisting}
(version 1)
(allow default)
(deny file-read*
  (regex #".*/\.ssh(/.*)?$")    (regex #".*/\.aws(/.*)?$")
  (regex #".*/\.gnupg(/.*)?$")  (regex #".*/\.kube(/.*)?$")
  (regex #".*/\.npmrc$")        (regex #".*/Library/Keychains(/.*)?$"))
(deny file-write*)
(allow file-write*
  (subpath "/private/.../upper_workspace")
  (subpath "/private/.../agent_home"))
(deny network-outbound)
(allow network-outbound (remote ip "localhost:51691"))
\end{lstlisting}
    Because \texttt{(deny network-outbound)} is enforced by the XNU kernel socket filter, even a prompt-injected child process that runs \texttt{curl --noproxy '*'} or raw TCP sockets cannot bypass the local Aegis Egress Proxy.
    \item \textbf{Tier 2 (\texttt{MicroVmSandboxDriver}, Cloud Control-Plane Interface):} Designed for multi-tenant cloud hosts, providing the control-plane specification and Scale-to-Zero \texttt{pause()}/\texttt{resume()} lifecycle state machine for hardware-virtualized VMM backends (\texttt{libkrun} / Firecracker~\cite{agache2020firecracker}).
\end{enumerate}

\paragraph{Identity-Pinned Zero-Trust Egress Proxy with Boundary Secret Injection.} To prevent credential exfiltration (Threat T4), agents inside Aegis OS never receive raw API keys in their environment variables or context windows. Instead, they are given opaque secret placeholders such as \texttt{\$AOS\_SECRET\_GH}. Outbound HTTP requests pass through \texttt{AegisEgressGateway::\allowbreak start\_local\_proxy\_with\_bound\_identity}, a local asynchronous L7 HTTP boundary gateway. When bound per sandbox, the listener pins the \texttt{AgentIdentity} at the TCP socket level so a compromised process cannot spoof \texttt{X-Aegis-Org} or \texttt{X-Aegis-Agent} headers. For each request, the gateway inspects the target \texttt{Host} header against the organization's domain allowlist and the secret vault's per-secret domain binding:
\begin{itemize}
    \item If \texttt{\$AOS\_SECRET\_GH} (bound exclusively to \texttt{api.github.com}) is sent in a header toward \texttt{api.github.com}, the proxy substitutes the real token \texttt{ghp\_...} at the network boundary.
    \item If a prompt-injected agent attempts to send \texttt{\$AOS\_SECRET\_GH} to an unauthorized host (e.g., \texttt{evil-exfil.org} or \texttt{webhook.site}), the TCP proxy immediately terminates the request with \texttt{HTTP/1.1 403 Forbidden} and records a security violation in \texttt{aos-recorder}.
\end{itemize}

\subsection{First-Class Inter-Agent IPC Bus and Content-Addressable Storage (\texttt{aos-ipc})}
\label{sec:ipc}

To elevate multi-agent collaboration from ad-hoc file polling to an OS-level primitive, \texttt{aos-ipc} provides a disk-synchronized, broadcast-enabled communication bus within each organization tenant $o_i$:
\begin{itemize}
    \item \textbf{Direct P2P Mailboxes and Correlated RPC:} Agents exchange structured envelopes via \texttt{ipc\_send}, \texttt{ipc\_recv}, \texttt{ipc\_request}, and \texttt{ipc\_reply}. Using \texttt{tokio::sync::broadcast} paired with an atomic disk state file (\texttt{ipc\_bus\_state.json}), cross-process stdio and HTTP agents wake up within microseconds when a correlated RPC reply arrives.
    \item \textbf{Topic Pub/Sub Fanout:} Agents subscribe to organizational topics (e.g., \texttt{topic://build-events}, \texttt{topic://security-alerts}) and broadcast events via \texttt{ipc\_publish}.
    \item \textbf{Zero-Copy CAS Artifact Handles:} Instead of embedding a 64 KB architecture specification or code patch inside an IPC message payload, the sender calls \texttt{org\_artifact\_publish}, which stores the blob in the organization's Content-Addressable Store and returns a compact 64-byte SHA-256 URI:
    \begin{center}
    {\footnotesize\texttt{artifact://acme/sha256:9f86d081884c7d65...}}
    \end{center}
    The sender attaches only this URI handle to the IPC envelope, reducing LLM context token consumption by \textbf{99.85\%}.
\end{itemize}

\subsection{Cedar-Aligned Policy Kernel and Formal Safety Invariants (\texttt{aos-policy})}
\label{sec:policy}

Every MCP syscall is evaluated by \texttt{AegisPolicyKernel::\allowbreak evaluate} before execution, following a deterministic five-stage evaluation hierarchy aligned with Cedar~\cite{cutler2024cedar}:
{\small
\begin{align}
    \text{R0 (Red-Line):} \; & \text{res} \in \mathcal{P}_{\text{forbidden}} \implies \textbf{Deny} \nonumber \\
    \text{R1 (Tenant):} \; & o_{\text{principal}} \neq o_{\text{target}} \implies \textbf{Deny} \nonumber \\
    \text{R2 (Lease):} \; & \exists \ell \in \mathcal{L}_{\text{active}}(o, u, \text{action}) \implies \textbf{Allow} \nonumber \\
    \text{R3 (Sandbox):} \; & \text{action} \in \mathcal{S}_{\text{internal}} \implies \textbf{Allow} \nonumber \\
    \text{R4 (Boundary):} \; & \text{action} \in \{\texttt{workspace\_commit}, \texttt{egress}\} \nonumber \\
    & \implies \textbf{RequireApproval}(\text{esc\_id}) \nonumber
\end{align}
}
where $\mathcal{P}_{\text{forbidden}} = \{\texttt{\textasciitilde/.ssh}, \allowbreak \texttt{\textasciitilde/.aws}, \allowbreak \texttt{/etc/shadow}, \allowbreak \texttt{/System}\}$ is the Ring-0 host red-line set that cannot be overridden even by an active lease, and $\mathcal{S}_{\text{internal}}$ encompasses all CoW filesystem operations, sandboxed process execution (\texttt{proc\_exec}), and intra-organization IPC/CAS operations. When a developer approves an escalation $\text{esc\_id}$ via \texttt{policy\_approve\_\allowbreak escalation}, they can optionally attach a Time-To-Live ($\text{TTL}$, e.g., 3,600 seconds), minting a \texttt{LeaseGrant} $\ell \in \mathcal{L}_{\text{active}}$ evaluated at R2 that permits subsequent commits within that session window with zero further prompts.

Together, the four kernel subsystems enforce three formal safety invariants:
\begin{itemize}
    \item \textbf{Invariant 1 (Pre-Commit Host Non-Interference):} For any sequence of agent syscalls $\tau = (s_1, \dots, s_k)$ where no $s_t$ is an approved \texttt{workspace\_commit}, the host directory tree $H$ satisfies $H(\tau) \equiv H_0$ ($\Delta H = \emptyset$), guaranteed jointly by VFS path canonicalization and Seatbelt/Bubblewrap kernel write confinement.
    \item \textbf{Invariant 2 (Zero Raw Secret Exposure):} For every secret entry $(p_j, v_j, \mathcal{D}_j)$ in the Egress Vault, the raw credential $v_j$ never appears in any agent process environment block, command-line argument, or standard I/O stream, and is injected into outbound network packets if and only if $\text{Host}(req) \in \mathcal{D}_j$.
    \item \textbf{Invariant 3 (Conflict-Safe Multi-Agent Commit):} Concurrent agent commits $(S_1, S_2, \dots, S_m)$ against baselines $(B_1, B_2, \dots, B_m)$ either produce a deterministic LCS Diff3 3-way merged host state preserving all disjoint line hunks (including multi-line insertions), or atomically abort without partial file mutation when overlapping baseline intervals $[b_{\text{start}}, b_{\text{end}})$ are modified differently by $H$ and $S_i$.
\end{itemize}

\section{Zero-Config Multi-Client Integration}
\label{sec:integration}

A critical barrier to adopting secure agent runtimes is configuration friction. Aegis OS provides a single command, \texttt{aegis-os install} (distributed via Homebrew \texttt{Formula/aegis-os.rb}), that non-destructively merges global configurations for all three major coding agent ecosystems:
\begin{enumerate}
    \item \textbf{Google Antigravity (\texttt{agy}):} Registers the \texttt{aegis-os} MCP server in \texttt{\textasciitilde/.gemini/config/mcp\_config.json}, installs a global runtime rule (\texttt{aegis-os-runtime.md}), and configures a \texttt{PreToolUse} hook (\texttt{aegis-os agy-hook}) that auto-allows \texttt{mcp\_aegis-os\_*} syscalls while intercepting dangerous direct host shell commands.
    \item \textbf{Anthropic Claude Code (\texttt{claude}):} Injects the MCP server entry into \texttt{\textasciitilde/.claude.json} and pre-populates \texttt{mcp\_\_aegis-os\_\_*} in \texttt{permissions.allow} inside \texttt{\textasciitilde/.claude/settings.json}.
    \item \textbf{OpenAI Codex CLI (\texttt{codex}):} Appends the \texttt{[mcp\_servers.aegis-os]} block to \texttt{\textasciitilde/.codex/config.toml}.
\end{enumerate}
When invoked with \texttt{--org auto --agent auto}, Aegis OS automatically derives the organization tenant $o_i$ from the active project directory name and the agent principal $u_i$ from the client binary identity, enabling instant cross-agent collaboration (\texttt{agy} + \texttt{claude} + \texttt{codex}) out of the box.

\subsection{Experiment 3 (RQ3): CoW Provisioning Latency, Storage Savings, and Syscall Overhead}

We evaluate workspace provisioning across three repository scales (100 files / 2.0 MB, 300 files / 17.6 MB, and 1,000 files / 78.1 MB) with 5 independent trials per scale. As shown in Table~\ref{tab:exp3a} and Figure~\ref{fig:exp3}, traditional full copying scales linearly with byte volume, requiring $98.33 \pm 3.75$ ms for the 1,000-file repository. By invoking APFS directory-tree \texttt{libc::clonefile}, Aegis OS provisions the exact same 1,000-file shadow workspace in \textbf{$5.75 \pm 1.55$ ms}---\textbf{17.1$\times$ faster} (and \textbf{17.2$\times$ faster} on the 300-file medium repository). To measure multi-agent storage overhead, we spawn 10 concurrent agent CoW workspaces and have each agent modify a realistic task working set of 6 files (Small), 12 files (Medium), and 25 files (Large). Because APFS CoW allocates new physical extents only for mutated files (while both \texttt{upper\_workspace/} and \texttt{baseline\_snapshot/} share unmodified extents), Aegis OS reduces 10-agent disk allocation by \textbf{94.0\%} (Small), \textbf{96.0\%} (Medium), and \textbf{97.5\%} (Large, 19.5 MB vs.\ 781.2 MB).

Table~\ref{tab:exp3b} reports the fine-grained latency distribution of kernel operations. In-process Cedar policy evaluation completes in \textbf{0.1 $\mu$s} (5.81M ops/sec), in-process IPC send/receive completes in \textbf{1.1 $\mu$s} (P50 = 1.0 $\mu$s), and a full end-to-end JSON-RPC \texttt{tools/call} (\texttt{fs\_read}) over a live loopback TCP socket to the HTTP daemon (\texttt{POST /mcp}) requires only \textbf{167.4 $\mu$s} (P50 = 172.1 $\mu$s, P99 = 292.2 $\mu$s, 5,804 ops/sec). Because typical LLM token generation latencies are $500,000$--$2,000,000$ $\mu$s (0.5--2.0 seconds), Aegis OS introduces \textbf{$<0.04\%$ end-to-end runtime overhead}.

\subsection{Experiment 4 (RQ4): Live 3-Agent Concurrent Rust Coding, Conflict Detection, and \texttt{cargo test} Verification}

We evaluate both non-overlapping structural edits and overlapping concurrent multi-agent edits across \texttt{agy-agent}, \texttt{claude-code}, and \texttt{codex-cli} on a live Rust crate (\texttt{src/lib.rs}):
\begin{itemize}
    \item \textbf{Concurrent Multi-Line Insertion and Function Edits (EXP 4A):} All three agents start from the same baseline \texttt{src/lib.rs}. \texttt{agy-agent} inserts a new 3-line helper function (\texttt{min\_fee()}) at the top of the file and updates \texttt{calc\_fee} (shifting all downstream line indices), while \texttt{claude-code} concurrently modifies \texttt{calc\_tax} and \texttt{codex-cli} modifies \texttt{calc\_discount}. In \textbf{Host-Shared-YOLO}, the final writer (\texttt{codex-cli}) silently clobbers the modifications of both \texttt{agy-agent} and \texttt{claude-code}, preserving only \textbf{1/3 (33.3\%)} of the features. In \textbf{Aegis-OS}, our LCS Diff3 engine (\texttt{three\_way\_merge\_lines}) aligns the unmodified anchor lines across the unequal-length files, preserving \textbf{3/3 (100\%)} of the features and passing a live \texttt{cargo test --offline} execution (\texttt{exit code 0}).
    \item \textbf{Overlapping Same-Line Conflict Detection (EXP 4B):} Across 10 live trials, both \texttt{agy-agent} and \texttt{codex-cli} concurrently modify \texttt{calc\_fee} with conflicting expressions. While \textbf{Host-Shared-YOLO} suffers a 100\% silent lost update (0/10 detected), \textbf{Aegis-OS} detects \textbf{10/10 (100\%)} of the overlapping line conflicts, atomically aborts the conflicting second commit without corrupting the host file, and returns an exact baseline line-number conflict diagnostic so the agent can coordinate via \texttt{aos-ipc}.
    \item \textbf{CAS Context Token Savings:} Replacing inline 64 KB specification handoffs with \texttt{artifact://} CAS URIs reduces IPC message payload bytes across 3 handoffs from 196,608 bytes ($\sim$49,152 tokens) to 294 bytes ($\sim$73 tokens), achieving a \textbf{99.85\% context token reduction} (Table~\ref{tab:exp4}).
\end{itemize}

\subsection{Experiment 5 (RQ5): Time-Travel Rollback and \texttt{cargo check} Verification}

Finally, we evaluate recovery from catastrophic agent hallucinations where an agent introduces syntax errors (\texttt{BROKEN\_RUST\_SYNTAX\_ERROR !!!}) across 10, 50, and 200 Rust module files (\texttt{src/mod\_*.rs}, 64 KB per module). As shown in Table~\ref{tab:exp5}, Aegis OS's atomic directory-tree \texttt{workspace\_rollback} restores all 200 corrupted modules in \textbf{$6.51 \pm 0.19$ ms} (\textbf{2.4$\times$ faster} than sequential file-by-file I/O restoration and over \textbf{10,000$\times$ faster} than multi-turn LLM-driven file reverts). Immediately after rollback, our benchmark harness executes \texttt{cargo check --offline} inside the restored shadow workspace, confirming 100\% compilation recovery across all scales.

\section{Cross-Platform Mapping, Discussion, and Limitations}
\label{sec:discussion}

\paragraph{Cross-Platform Kernel Primitive Duality (macOS vs.\ Linux).} While our live empirical evaluation in \S\ref{sec:eval} was conducted on Apple Silicon (\texttt{macos-aarch64}), every Aegis OS subsystem is architected around platform-agnostic Rust traits (\texttt{TransactionalWorkspace}, \texttt{SandboxDriver}) that map cleanly onto native Linux kernel primitives, as detailed in Table~\ref{tab:crossplatform}. On Linux hosts formatted with Btrfs or XFS (\texttt{reflink=1}), \texttt{aos-vfs} uses extent-level \texttt{FICLONE} reflinks~\cite{rodeh2013btrfs} (or \texttt{OverlayFS} upperdirs~\cite{wright2004unionfs} on ext4) to achieve the same $O(1)$ CoW workspace provisioning. Similarly, \texttt{aos-sandbox} executes \texttt{/usr/bin/bwrap} on Linux to enforce unprivileged user, mount, PID, and network namespaces, while Tier 2 provides the control-plane interface for \texttt{libkrun}/Firecracker microVMs~\cite{agache2020firecracker}.

\paragraph{Filesystem Read Denylist vs.\ Allowlist Trade-offs on Developer Workstations.} On Linux (\texttt{bwrap}), mounting an isolated root filesystem with selective read-only bind mounts (\texttt{--ro-bind /usr /usr}) naturally enforces a strict read allowlist. On macOS, however, XNU's dynamic linker (\texttt{dyld} shared cache), Xcode toolchains, and Homebrew libraries traverse numerous system paths under \texttt{/System}, \texttt{/Library}, and \texttt{/opt/homebrew}. Consequently, our macOS Seatbelt profile combines a \emph{strict allowlist on file writes} (\texttt{(deny file-write*)}) with a \emph{targeted regex denylist on file reads} covering high-value credential stores (\texttt{.ssh}, \texttt{.aws}, \texttt{.gnupg}, \texttt{.kube}, \texttt{.config/gh}, \texttt{.npmrc}, \texttt{.pypirc}, and \texttt{Library/Keychains}). Users requiring strict read isolation from sibling source repositories on macOS can additionally pass custom \texttt{(deny file-read* (subpath ...))} rules for their parent project directories while keeping toolchain paths readable.

\paragraph{HTTPS TLS Termination and Boundary Secret Injection.} In our current implementation, \texttt{AegisEgressGateway} operates as an L7 HTTP boundary gateway and MCP \texttt{egress\_http\_request} sanitizer, pinning agent identities per listener socket (\texttt{start\_local\_proxy\_with\_bound\_identity}) and enforcing kernel-level Seatbelt \texttt{(deny network-outbound)} so child processes cannot bypass the local proxy. When legacy CLI binaries inside \texttt{proc\_exec} initiate direct TLS (\texttt{HTTPS CONNECT}) tunnels, inspecting headers requires the local proxy to terminate TLS using a session-scoped ephemeral Certificate Authority (CA) injected into the sandbox's \texttt{SSL\_CERT\_FILE} environment variable. Extending \texttt{aos-egress} with automated per-sandbox ephemeral CA generation and full upstream TLS forwarding is a natural engineering extension.

\paragraph{Syntactic 3-Way Merging vs.\ Semantic Integration Conflicts.} Our LCS Diff3 3-Way Merge Engine (\texttt{three\_way\_merge\_lines})~\cite{khanna2007formal} resolves 100\% of disjoint line-level edits (including multi-line insertions) and catches 100\% of overlapping line conflicts (Table~\ref{tab:exp4}). However, two agents could make syntactically disjoint edits that introduce a \emph{semantic conflict} (e.g., Agent A renames a function signature at Line 10 while Agent B adds a call to the old function name at Line 120). Aegis OS mitigates semantic conflicts by allowing the committing agent (or a pre-commit verification hook) to execute \texttt{cargo test} inside the sandbox after merging peer changes from \texttt{host/} into \texttt{upper\_workspace/} prior to finalizing \texttt{workspace\_commit}, and by supporting instant \texttt{workspace\_rollback} if post-merge compilation fails.

\section{Related Work}
\label{sec:related}

\paragraph{LLM Agent Sandboxes and Prompt Injection Defenses.} Benchmarks such as SWE-bench~\cite{jimenez2024swebench}, SWE-agent~\cite{yang2024sweagent}, OpenHands~\cite{wang2025openhands}, ToolEmu~\cite{ruan2024toolemu}, AgentDojo~\cite{debenedetti2024agentdojo}, and InjecAgent~\cite{zhan2024injecagent} highlight both the capabilities and vulnerability of tool-using agents to indirect prompt injection~\cite{greshake2023not}. Recent defenses such as SecGPT~\cite{wu2024secgpt}, CaMeL~\cite{debenedetti2025camel}, and FIDES~\cite{costa2025fides} propose information-flow control or dual-LLM privilege separation at the prompt/interpreter level. Aegis OS is complementary to model-level defenses: it enforces mandatory access control at the \emph{operating system kernel and network boundary} regardless of how the agent planner is implemented. Unlike container-per-task sandboxes (e.g., Docker), which incur seconds of startup latency and isolate agents from the developer's live local repository, Aegis OS combines sub-6ms APFS CoW shadow workspaces~\cite{rodeh2013btrfs,wright2004unionfs} with Seatbelt/Bubblewrap mandatory access control~\cite{kim2013mbox} and an LCS Diff3 3-Way Merge Engine~\cite{khanna2007formal} directly over the live repository.

\paragraph{Agent Operating Systems and Multi-Agent Frameworks.} AIOS~\cite{mei2024aios} integrates an LLM kernel scheduler above application agents, while AutoGen~\cite{wu2023autogen} and MetaGPT~\cite{hong2024metagpt} orchestrate multi-agent conversations in Python. In contrast, Aegis OS adopts a strict ``Environment Kernel Only'' design aligned with classical capability systems such as Capsicum~\cite{watson2010capsicum}, Mbox~\cite{kim2013mbox}, Cedar authorization~\cite{cutler2024cedar}, and Firecracker microVMs~\cite{agache2020firecracker}, serving any MCP-compatible client (\texttt{agy}, \texttt{claude}, \texttt{codex}) without dictating agent reasoning logic.

\section{Conclusion}
\label{sec:conclusion}

We presented \textbf{Aegis OS}, a transactional, multi-tenant Agent Operating System Runtime that resolves the Security--Autonomy Dilemma for autonomous coding agents. By combining APFS Copy-on-Write shadow workspaces, LCS Diff3 3-Way multi-agent merge commits, kernel-enforced Seatbelt/Bubblewrap sandboxes with outbound network confinement, Zero-Trust boundary secret injection, and first-class IPC + CAS primitives, Aegis OS eliminates 94.19\%--99.88\% of human confirmation prompts while reducing adversarial attack success from 100.0\% to 0.0\%.
